# CH 01. 네트우크 프로그래밍과 소켓의 이해

## 01-1 네트워크 프로그래밍과 소켓의 이해
네트워크로 연결되어 있는 서로 다른 두 컴퓨터가 데이터를 주고받을 수 있도록 하는 것이 네트워크 프로그래밍이다. 운영체제에서 '소켓(Socket)'이라는 물리적으로 연결된 네트워크상에서의 데이터 송수신에 사용할 수 있는 소프트웨어적인 장치를 제공한다.

소켓은 크게 TCP와 UDP, 두 가지로 나뉜다. 여기서는 TCP를 먼저 소개한다. 소켓을 전화기에 비유해서 설명하면 아래와 같다.
- **전화를 받는 순서**  
1. 전화를 받기 위해서는 가장 먼저 전화기가 필요하다.
2. 전화기에 전화번호를 설정한다.
3. 전화가 걸려오는 것을 기다린다.
4. 전화벨이 울리면 전화를 받는다.

이 과정을 소켓에 대입하면 아래와 같다.
- **소켓을 연결하는 순서**
1. socket() 함수를 호출하여 소켓을 생성한다.
2. bind() 함수를 호출하여 IP 주소와 PORT 번호를 할당한다.
3. listen() 함수를 호출하여 연결요청이 가능한 상태로 변경한다.
4. accept() 함수를 호출하여 연결요청을 수락한다.

실제 코드 구성은 아래 링크에서 설명한다.  
["Hello world!" 서버 프로그램 예제 코드](./01_hello_world.md)

리눅스 기반에서 특정 코드를 컴파일 및 실행하려면 아래와 같은 명령어를 입력한다.  
```bash
# .c 프로그램 컴파일
gcc [소스코드] -o [실행파일 이름]

# .cpp 프로그램 컴파일
g++ [소스코드] -o [실행파일 이름]

# 프로그램 실행(필요 시 뒤에 인수 추가)
./[실행파일 이름] [인수]
```
실행 과정에서 로컬에서 서버와 클라이언트를 모두 실행한다면 127.0.0.1 루프백 주소를 사용하면 된다.
만약 서버와 클라이언트를 실행하는 PC가 다르다면 서버의 주소를 사용하면 된다.  

## 01-2 리눅스 기반 파일 조작하기
리눅스에서의 소켓조작은 파일조작과 동일하게 간주된다. 즉, 리눅스는 소켓을 파일의 일종으로 구분한다. 따라서 파일 입출력 함수를 소켓 입출력에 사용할 수 있다.

파일 디스크립터란 시스템으로부터 할당 받은 파일 또는 소켓에 부여된 정수를 의미한다. 리눅스는 아래와 같이 표준 입출력 및 표준 에러에도 파일 디스크립터를 할당하고 있다.

| 파일 디스크립터 | 대상                    |
| :--: | -- |
| 0        | 표준입력: Standard Input  |
| 1        | 표준출력: Standard Output |
| 2        | 표준에러: Standard Error  |

- **파일 열기**
```cpp
int open(const char *path, int flag);
// 성공 시 파일 디스크립터, 실패 시 -1 반환
```
flag에 전달할 수 있는 값과 그 의미는 다음과 같으며, 하나 이상의 정보를 비트 OR 연산자로 묶어서 전달할 수 있다.

| 오픈 모드 | 의미 |
| :--: | -- |
| `O_CREAT`  | 필요하면 파일을 생성 |
| `O_TRUNC`  | 기존 데이터 전부 삭제 |
| `O_APPEND` | 기존 데이터 보존하고, 뒤에 이어서 저장 |
| `O_RDONLY` | 읽기 전용으로 파일 오픈 |
| `O_WRONLY` | 쓰기 전용으로 파일 오픈 |
| `O_RDWR`   | 읽기, 쓰지 겸용으로 파일 오픈 |

- **파일 닫기**
```cpp
int close(int fd);
// 성공 시 0, 실패 시 -1 반환
```
파일 디스크립터에 해당하는 파일을 종료하는 함수이다. 리눅스는 해당 함수를 소켓을 닫는 상황에서도 사용한다.

- **파일에 데이터 쓰기**
```cpp
ssize_t write(int fd, const void* buf, size_t nbytes);
// 성공 시 전달한 바이트 수, 실패 시 -1 반환
```
파일에 데이터를 전송하는 함수이다. 리눅스에서는 해당 함수를 소켓을 통한 데이터 전송 상황에서도 사용한다.
여기서 `ssize_t`는 typedef 선언을 통해 `signed int`로 정의되어 있다.

## 01-3 윈도우 기반으로 구현하기
윈도우 소켓을 기반으로 프로그램을 개발하기 위해서는 기본적으로 다음 두 가지를 진행해야 한다.  
1. winsock2.h 헤더파일을 포함한다.
2. ws2_32.lib 라이브러리를 링크시켜야 한다.

- **winsock2.h 헤더파일 포함**

매우 단순하게 include로 포함하면 된다.
```cpp
#include <winsock2.h>
```

- **ws2_32.lib 라이브러리 링크**

라이브러리 링크는 두 가지 방법이 있다.  
1. Visual Studio 기준으로 프로젝트 '속성'을 변경하는 방법  
2. 전처리기로 명시하는 방법

1번 방법은 다음과 같이 따라가면 된다.

`프로젝트 속성 페이지(ALT + F7)` -> `구성 속성` -> `링커` -> `입력`-> `추가 종속성`을 선택한다. 추가 종속성에서 `ws2_32.lib`를 직접 써 넣으면 된다.  

2번 방법은 다음 코드를 소스 코드 최상단에 작성하면 된다.  
```cpp
#pragma comment(lib, "ws2_32.lib")
```

윈도우 소켓 프로그래밍을 할 때에는 반드시 WSAStartup 함수를 호출해서, 프로그램에서 요구하는 윈도우 소켓의 버전을 알리고, 해당 버전을 지원하는 라이브러리의 초기화 작업을 진행해야 한다.  
```cpp
int WSAStartup(WORD wVersionRequested, LPWSADATA lpWSAData);
/* 
성공 시 0, 실패 시 0이 아닌 에러코드 값 반환
wVersionRequested: 프로그래머가 사용할 윈도우 소켓의 버전정보 전달
lpWSAData: WSADATA라는 구조체 변수의 주소 값 전달
*/
```

초기화된 라이브러리의 해제 방법은 아래와 같다.  
```cpp
int WSACleanup(void);
// 성공 시 0, 실패 시 SOCKET_ERROR 반환
```
이 함수를 호출하면 윈도우 소켓과 관련된 함수의 호출이 불가능해진다. 따라서 더 이상 관련 함수의 호출이 불필요할 때 사용한다. 프로그램이 종료되기 직전에 호출하는 것이 보통이다.
