# CH 11. 프로세스간 통신(Inter Process Communication)

## 11-1 프로세스간 통신의 기본 개념

프로세스간 통신이 가능하다는 것은 두 프로세스가 데이터를 주고 받을 수 있다는 의미가 되며, 이렇게 되기 위해서는 두 프로세스가 동시에 접근 가능한 메모리 공간이 있어야 한다.

- 프로세스간 통신의 기본 이해

프로세스간 통신은 생각보다 어렵지 않은 개념이다. 프로세스 A가 프로세스 B에게 다음과 같이 말한다면 이 역시 프로세스간 통신의 규칙이 된다.
> 내게 빵이 하나 생기면 bread의 값을 1로 변경하겠다. 그리고 그 빵을 먹어버리면 변수 bread의 값을 0으로 다시 변경하겠다. 그러니 너는 변수 bread의 값을 통해서 내 상태를 파악해라.

즉, 프로세스 A는 변수 bread를 통해서 자신의 상태를 프로세스 B에게 말한 셈이고, 프로세스 B는 변수 bread를 통해서 프로세스 A가 한 말을 들은 셈이다.<br>
하지만 CH 10의 내용에 따르면 프로세스는 서로 완전히 별개의 메모리 구조를 지닌다. 따라서 fork 함수호출을 통해서 생성된 자식 프로세스 조차 부모 프로세스와 메모리 공간을 조금도 공유하지 않는다.

---

- 파이프(PIPE) 기반의 프로세스간 통신

두 프로세스간 통신을 위해서는 파이프라는 것을 생성해야 한다. 이 파이프는 소켓과 마찬가지로 운영체제에 속하는 자원이다. 즉, 운영체제가 마련해 주는 메모리 공간을 통해서 두 프로세스는 통신을 하게 된다. 파이프 생성 함수는 다음과 같다.
```cpp
#include <unistd.h>

int pipe(int filedes[2]);
// 성공 시 0, 실패 시 -1 반환
```
길이가 2인 int형 배열의 주소 값을 인자로 전달하면서 위의 함수를 호출하면 배열에는 두 개의 파일 디스크립터가 담긴다. 그리고 이들 각각은 파이프의 출구와 입구로 사용이 된다.<br>
하나의 파이프로도 부모 프로세스와 자식 프로세스는 충분히 통신을 할 수 있다. 각각 입력과 출력 경로에 접근하면 되기 때문이다.

---

- 파이프(PIPE) 기반의 프로세스간 양방향 통신

이번에는 하나의 파이프를 통해서 두 프로세스가 양방향으로 데이터를 주고 받는 상황을 생각해 보자. 일단 가능은 하다. 하지만 문제점이 있다.<br>
파이프에 전달된 데이터의 소유권은 다음과 같은 규칙으로 정해진다.
> 파이프에 데이터가 전달되면, 먼저 가져가는 프로세스에게 이 데이터가 전달된다.

파이프에 있는 데이터는 임자가 없는 데이터가 된다. 즉, 데이터의 소유권을 가진 주체가 없다는 것이다. 따라서 read 함수호출을 통해서 먼저 데이터를 읽어 들이는 프로세스에게 데이터가 전달된다. 이러한 특성 때문에 부모 프로세스가 자식 프로세스에게 전달한 데이터를 부모 프로세스 자신이 가져가게 되는 상황이 발생할 수도 있다. 그러면 자식 프로세스는 부모 프로세스가 전달한 데이터를 수신하지 못 하고 계속 기다리는 꼴이 된다.<br>
어떻게 하면 이런 문제를 해결할 수 있을까? 간단하다. 파이프를 두 개 만들어서 각각 입력과 출력을 담당하면 된다.

## 11-2 프로세스간 통신의 적용

파이프를 네트워크 코드에 적용해보자. 사실 프로세스간 통신은 서버의 구현에 직접적인 연관이 없다. 그러나 운영체제를 이해한다는 측면에서 의미가 있다.

- 메시지를 저장하는 형태의 에코 서버

CH 10에서 제시한 에코 서버를 확장해서 클라이언트가 전송하는 문자열을 전달되는 순서대로 파일에 저장하는 기능을 추가할 것이다.<br>
이를 위해서 별도의 프로세스를 생성하고, 클라이언트에게 서비스를 제공하는 프로세스로부터 문자열 정보를 수신하게끔 할 수 있다. 그리고 이 과정에서 파이프를 사용할 것이다.
