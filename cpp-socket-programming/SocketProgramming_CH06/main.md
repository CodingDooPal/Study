# CH 06. UDP 기반 서버/클라이언트

## 06-1 UDP에 대한 이해
- UDP 소켓의 특성<br>
1. `UDP 소켓`은 TCP 소켓과 다르게 `신뢰할 수 없는 전송방법`을 제공한다.
2. TCP보다 훨씬 `간결한 구조`로 설계되어있다. ACK와 같은 응답 메시지를 보내지 않고, SEQ와 같이 패킷에 번호를 부여하지도 않는다. 때문에 `상황에 따라 TCP보다 좋은 성능`을 보여준다.
3. 신뢰성은 떨어지지만 그렇다고 데이터의 손실이 자주 발생하는 것은 아니다. 따라서 `신뢰성보다 성능이 중요시되는 상황에서 고려`할 수 있다.

UDP와 TCP를 구분하는 가장 큰 차이점은 `흐름제어(Flow Control)`의 유무이다. TCP는 신뢰성 있는 데이터의 송수신을 위해 흐름제어를 하지만 `UDP는 흐름제어를 하지 않는다.`

- UDP의 내부 동작원리<br>
목적지 호스트까지의 이동은 IP가 맡는다. `UDP는 호스트로 수신된 패킷의 PORT 정보를 참조하여 최종 목적지인 UDP 소켓에 전달`한다.<br>
TCP 소켓은 IP가 목적지 호스트에 데이터를 전송할 때 흐름제어를 하지만 `UDP는 흐름제어를 하지 않기 때문에 IP의 역할에 관여하지 않는다.`

- UDP의 사용<br>
압축파일과 같이 `일부가 손실되면 제 기능을 하는 것이 어려운 경우에는 반드시 TCP를 기반`으로 송수신을 해야 한다. 그러나 영상 및 음악 스트리밍과 같이 `실시간으로 서비스`를 해야하고`(성능 요구)`, 원본 데이터의 일부가 손실되어도 크게 문제가 없는 경우에는 `UDP를 기반`으로 송수신 하는 것을 고려할 수 있다.

## 06-2 UDP 기반 서버/클라이언트의 구현
- UDP에서의 서버와 클라이언트 특징<br>
1. UDP 서버, 클라이언트는 TCP와 같이 `연결된 상태로 데이터를 송수신하지 않는다.` 따라서 연결 설정을 위한 `listen` 함수와 `accept` 함수의 호출은 `불필요`하다.
2. TCP에서는 소켓과 소켓의 관계가 일대일이다. 이러한 연결 때문에 1개의 서버가 10개의 클라이언트에게 서비스를 제공하려면 서버 소켓을 제외하고 10개의 소켓을 더 필요로 했다. 하지만 UDP에서는 `하나의 소켓`만 있으면 다른 소켓과 송수신이 가능하다.

- UDP 기반의 데이터 입출력 함수<br>
> **sendto(데이터 송신)**
```cpp
#include <sys/socket.h>

ssize_t sendto(int sock, void *buff, size_t nbytes, int flags, struct sockaddr *to, socklen_t addrlen);
// 성공 시 전송된 바이트 수, 실패 시 -1 반환
```

> **recvfrom(데이터 수신)**
```cpp
#include <sys/socket.h>

ssize_t recvfrom(int sock, void *buff, size_t nbytes, int flags, struct sockaddr *from, socklen_t *addrlen);
// 성공 시 전송된 바이트 수, 실패 시 -1 반환
```

두 함수 모두 TCP 기반의 입출력 함수인 write, read와 다르게 `목적지 주소정보`를 요구하고 있다.

UDP 데이터는 일대일 연결을 하는 TCP와 다르게 `발신지가 일정하지 않다.` sendto 함수는 발신지 정보를 얻을 수 있도록 to에 목적지 주소 정보를 담고 있는 sockaddr 구조체 변수의 주소 값을, addrlen에 to로 전달된 주소 값의 구조체 변수 크기를 전달한다.

같은 원리로 recvfrom 함수는 from에 발신지 정보를 채워 넣을 sockaddr 구조체 변수의 주소 값을, addrlen에 from으로 전달된 주소에 해당하는 구조체 변수의 크기정보를 담고있는 변수의 주소 값을 전달한다.

- UDP 클라리언트 소켓의 주소정보 할당<br>
TCP 클라이언트는 `connect` 함수호출 시 자동으로 `IP`와 `PORT 번호`를 소켓에 할당한다. 하지만 UDP는 연결을 하지 않기 때문에 어느 시점에 IP와 PORT 번호가 할당되는지 의문이 생길 수 있다.<br><br>
UDP 프로그램은 기본적으로 데이터를 전송하는 `sendto 함수호출 이전`에 해당 소켓에 주소정보가 할당되어 있어야 한다. 보통 `bind 함수가 호출될 때` 주소정보를 할당한다. 만약 sendto 함수호출 시까지 주소 정보가 할당되지 않았다면, `sendto가 처음 호출되는 시점`에 해당 소켓에 IP와 PORT 번호가 자동으로 할당된다.

## 06-3 UDP의 데이터 송수신 특성
`TCP 기반`에서 송수신하는 데이터에는 `경계가 존재하지 않는다.` 이는 데이터 송수신 과정에서 호출하는 입출력함수의 호출횟수가 큰 의미를 지니지 않는 것을 의미한다.<br>
반대로 `UDP 가반`에서 송수신하는 데이터에는 `경계가 존재한다.` 따라서 데이터 송수신 과정에서 호출하는 `입출력함수의 호출횟수를 완벽히 일치시켜야 한다.` 예를 들어 세 번의 출력 함수를 통해 전송된 데이터는 세 번의 입력함수 호출이 있어야 데이터를 전부 수신할 수 있다.
