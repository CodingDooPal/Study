# CH 07. 소켓의 연결종료

## 07-1 TCP 기반의 Half-close
- 일방적인 연결종료의 문제점<br>
리눅스의 `close`와 윈도우의 `closesocket` 함수호출은 `완전종료`를 의미한다. 완전종료는 `데이터를 전송/수신하는 것이 불가능한 상황`을 의미한다.<br><br>
호스트 A가 마지막 데이터를 전송하고 나서 close 함수로 연결을 종료했다고 가정해보자. 이렇게 되면 호스트 A는 호스트 B가 전송하는 데이터를 무조건 받아야 할지라도 수신하지 못 하고, 데이터는 소멸된다.<br><br>

- 소켓과 스트림<br>
소켓을 통해서 두 호스트가 연결되면, 그 다음부터는 상호간에 데이터의 송수신이 가능한 상태가 된다. 이러한 상태를 `스트림이 형성된 상태`라 한다.<br><br>
두 호스트의 소켓이 연결되면, 각 호스트 별로 입력 스트림과 출력 스트림이 형성된다. `Half-close`는 한 번에 두 스트림을 모두 끊어버리는 것이 아니라, 이 중 `하나의 스트림만 끊는 것`이다.<br><br>

- Half-close를 위한 shutdown 함수<br>
```cpp
#include <sys/socket.h>

int shutdown(int sock, int howto);
// 성공 시 0, 실패 시 -1 반환
```
위의 함수호출 시 두 번째 매개변수에 전달되는 인자에 따라서 종료의 방법이 결정된다.
| 매개변수 | 역할 |
| :--: | -- |
| `SHUT_RD` | 입력 스트림 종료 |
| `SHUT_WR` | 출력 스트림 종료 |
| `SHUT_RDWR` | 입출력 스트림 종료 |
<br>

- Half-close가 필요한 이유<br>
파일과 같은 데이터를 전송하는 서버는 단순히 데이터를 연속해서 전송하면 된다. 하지만 `클라이언트는 언제까지 데이터를 수신해야 할지 알 수 없다.` 파일의 끝을 의미하는 문자를 사용하는 것도 힘들다. 해당 문자와 일치하는 데이터가 파일에 존재할 수 있기 때문이다.<br><br>
이러한 문제를 해결하기 위해 `서버는 파일의 전송이 끝났음을 알리는 목적으로 EOF를 전송`한다. `클라이언트는 EOF의 수신을 함수의 반환 값을 통해서 확인이 가능`하기 때문에 파일에 저장된 데이터와 중복될 일도 없다.<br><br>
`서버는 출력 스트림을 종료해서 클라이언트에게 EOF를 전송`할 수 있다. close 함수호출을 통해서 입출력 스트림을 모두 종료해도 되지만, 이럴 경우 상대방이 전송하는 데이터를 더 이상 수신 못한다는 문제가 있다. 따라서 shutdown 함수호출을 통해서 서버의 출력 스트림만 Half-close 해야 한다. 이렇게 하면 EOF도 전송되고 입력 스트림은 종료되지 않기 때문에 데이터를 수신할 수 있다.<br><br>
